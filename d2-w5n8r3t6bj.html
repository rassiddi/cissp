Classification concepts — tap to expand
Who classifies data?
The Data Owner (Senior Management) is responsible for classifying data. Classification is based on the value of the data and impact if disclosed, altered, or destroyed. Not the IT department.
Classification criteria
Determined by: value to the organisation, age of the data, usefulness, and level of damage caused if disclosed. Sensitivity labels are based on sensitivity and need to keep information secret.
Declassification
Classification levels can change over time. Declassification must be formally approved by the Data Owner. Re-classification can also increase protection levels if risk changes.
Sensitivity labels (MAC)
Used in Mandatory Access Control (MAC) systems. Labels attached to objects (data) and subjects (users). User clearance must be ≥ data classification level to gain access.
Asset inventory
All assets must be identified, assigned an owner, valued, and classified before controls can be applied. Includes tangible (hardware, media) and intangible (data, IP, reputation) assets.
Scoping & tailoring
Scoping — identifying which parts of a framework apply to your environment. Tailoring — customising a baseline of controls to fit your organisation's specific needs and risk posture.
Data roles — accountability not legal ownership
In the CISSP context, "ownership" means accountability for the data — not legal title. Each role carries distinct responsibilities that cannot be delegated away.
Data Owner
  • Senior management / executive
  • Classifies and values data
  • Assigns classification labels
  • Approves access control policy
  • Ultimately accountable
Data Custodian
  • IT / technical staff
  • Implements owner's controls
  • Performs backups & recovery
  • Maintains audit logs
  • Day-to-day data security
Data User
  • Any person accessing data
  • Accesses only what is needed
  • Follows security policy
  • Reports security incidents
  • Responsible for proper use
Data Controller
  • GDPR context
  • Determines purpose & means
  • Primary legal accountability
  • Must appoint DPO if required
  • Breach notification obligation
Data Processor
  • GDPR context
  • Processes on behalf of controller
  • Third-party / cloud providers
  • Bound by data processing agreement
  • Cannot sub-process without consent
Data Subject
  • Individual the data is about
  • Right to access their data (SAR)
  • Right to rectification
  • Right to erasure
  • Right to object to processing
System roles
System Owner
Responsible for the system that processes data. Creates and maintains the security plan for the system. Different from Data Owner — focuses on infrastructure not information.
System Administrator
Technical role implementing controls on the system per the System Owner's direction. Manages user accounts, patches, and access configurations.
Security Administrator
Manages security-specific configurations — firewall rules, IDS/IPS settings, encryption keys, and security policies. Reports to CISO.
DPO — Data Protection Officer
Required under GDPR for organisations processing large volumes of personal data. Advises on compliance, monitors adherence, acts as contact point for supervisory authorities.

Security controls must be applied at EVERY stage of the lifecycle — not just at rest or in transit.
Data states & required protection
Data at rest
Stored on media — hard drives, SSDs, tapes, cloud. Controls: AES-256 encryption at rest, access controls, physical security, full-disk encryption (FDE), database encryption.
Data in transit
Moving across a network or between systems. Controls: TLS/SSL, VPN, IPSec, SFTP, HTTPS. Never send sensitive data over unencrypted channels.
Data in use
Actively being processed in RAM or CPU. Hardest state to protect. Controls: Trusted Execution Environments (TEE), memory encryption, DLP tools, endpoint controls, screen lock, clear desk policy.
Asset valuation
Tangible assets
Physical assets: hardware, servers, media, facilities. Valued in monetary terms. Easier to quantify for QRA calculations (AV, SLE, ALE).
Intangible assets
Non-physical: data, intellectual property, brand reputation, trade secrets, customer trust. Often harder to value but frequently the most critical. Loss can be catastrophic and irreversible.
ACV vs replacement cost
ACV (Actual Cash Value) = current depreciated value. Replacement cost = cost to replace with new equivalent. Insurance policies may use either — understand which applies for DRP/BCP planning.
Retention concepts — tap to expand
Retention policy
Defines how long different categories of data are kept. Driven by: legal/regulatory requirements, business need, litigation hold, and cost. Data must not be kept longer than necessary — excessive retention increases risk and liability.
Legal / litigation hold
Suspends normal destruction schedules when litigation is anticipated. All potentially relevant data must be preserved. Failure to preserve = spoliation — can result in court sanctions. Relates to EDRM Step 3: Preservation.
Vital records program
Identifies and protects records critical for business operations and legal compliance. Key records must have offsite backup copies and be part of BCP/DRP. Examples: contracts, financial records, IP documentation.
Data minimisation
Collect only what is needed for a specific, stated purpose. GDPR principle. Reduces risk — you cannot breach data you do not have. Excess data collection creates unnecessary liability.
Data remanence
Residual data that remains on media after deletion attempts. Deleting a file or formatting media does NOT remove data — it only marks sectors as available. True destruction requires degaussing, overwriting, or physical destruction.
Object reuse
When storage media is reassigned to a new user/process, residual data from the previous use may be accessible. OS must clear/overwrite memory/disk before reuse. Relevant to both RAM and storage media sanitisation.

Privacy core concepts — tap to expand
PII
Personally Identifiable Information — any data that can identify an individual directly (name, SSN, passport) or indirectly (IP address, device ID, location data). Gathering PII mandates addressing privacy obligations.
PHI
Protected Health Information — under HIPAA. Any health information that can identify a patient. Includes medical records, diagnoses, treatment plans, insurance info. Requires administrative, physical, and technical safeguards.
Privacy by design
Privacy built into systems from the start — not added as an afterthought. GDPR principle. 7 foundations: proactive, privacy as default, embedded in design, full functionality, end-to-end security, visibility, respect for user privacy.
Anonymisation vs pseudonymisation
Anonymisation — data cannot be re-identified even with additional info. Falls outside GDPR scope. Pseudonymisation — data replaced with pseudonyms; re-identification is possible with additional data. Still personal data under GDPR.
Valid consent (GDPR)
Must be: freely given, specific, informed, and unambiguous. Pre-ticked boxes are NOT valid consent. Withdrawal must be as easy as giving consent. Children under 16 require parental consent (member states can lower to 13).
Cross-border data transfer
GDPR restricts transfer of personal data outside EEA. Mechanisms: Standard Contractual Clauses (SCCs), Binding Corporate Rules (BCRs), Adequacy decisions. Privacy Shield was invalidated by Schrems II ruling (2020).
GDPR — 6 lawful bases for processing (must satisfy at least one)
1Consent — data subject has given clear, specific, informed, unambiguous consent
2Contract — processing is necessary to perform a contract with the data subject
3Legal obligation — processing is required to comply with the law
4Vital interests — necessary to protect someone's life
5Public task — processing for an official function or task in the public interest
6Legitimate interests — balance between org interest and data subject rights (requires Legitimate Interests Assessment — LIA)
GDPR — data subject rights
Right to access (SAR)
Subject Access Request — can request a copy of their personal data held. Must be fulfilled within 30 days. No charge for first request.
Right to rectification
Right to correct inaccurate or incomplete personal data without undue delay.
Right to erasure
"Right to be forgotten." Applies when: no longer necessary, consent withdrawn, unlawfully processed. Not absolute — exemptions exist for legal obligations and public interest.
Right to portability
Receive personal data in a structured, machine-readable format and transmit it to another controller.
Right to restrict
Data subject can request processing be temporarily halted while accuracy or lawfulness is contested.
Right to object
Object to processing based on legitimate interests or direct marketing. Controller must stop unless it can demonstrate compelling legitimate grounds.
NIST SP 800-88 — three sanitisation levels
Clear
Logical overwrite. Protects against simple non-invasive recovery. Suitable for reuse in same security domain.
Purge
Overwriting, degaussing, or cryptographic erasure. Protects against lab-level attack. Media may be reused at same/lower classification.
Destroy
Disintegration, pulverisation, melting, incineration, shredding. Highest assurance. Media cannot be reused.
Sanitisation methods compared
Deleting a file or formatting media does NOT destroy data — it only removes the directory entry. Forensic tools can reconstruct data. Proper sanitisation is mandatory before disposal or reuse.

Media-specific guidance — tap to expand
HDD (magnetic)
Overwriting (1–7 pass), degaussing, or physical shredding. Degaussing destroys the servo track, rendering the drive inoperable. NIST 800-88: 1-pass overwrite is sufficient for modern HDDs.
SSD / flash media
Overwriting unreliable due to wear levelling — some blocks may not be overwritten. Best methods: cryptographic erasure (if encrypted from start), ATA Secure Erase command, or physical shredding.
Magnetic tapes
Degaussing or incineration. Degaussing is most practical for large tape libraries. Physical destruction by shredding offers highest assurance.
Optical media (CD/DVD)
Degaussing is NOT effective (no magnetic encoding). Physical destruction only: shredding, disintegration, or incineration. Use optical media shredders certified for classified destruction.
Paper documents
All documents must be shredded or incinerated before discarding. Use cross-cut or micro-cut shredders — strip-cut can be reconstructed. Enforce a clear desk policy for sensitive material.
RAM / volatile memory
RAM retains data briefly after power-off (cold boot attack risk). Mitigation: physical security, memory encryption, disable external boot devices. Data is generally cleared by reboot but brief residual traces may exist.
