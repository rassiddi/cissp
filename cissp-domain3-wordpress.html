Cryptography foundations
Goals of Cryptography — P A I N: Privacy (Confidentiality) · Authentication · Integrity · Non-Repudiation. Kerckhoff's Principle: the algorithm must be made public for examination and testing — only the key is kept secret.
Key concepts
Key Space = 2ⁿ where n is the bit size. AES-256 key space = 2²⁵⁶. Work Function = time and effort required to break a cryptosystem — indicates its strength. Nonce = unique random number used once (Initialization Vector / IV). Zero Knowledge Proof = sharing proof without sharing actual knowledge.
Cipher types
Substitution Cipher: replaces characters (e.g. Caesar cipher ROT3). Transposition Cipher: rearranges letters. Block Cipher: encrypts in fixed blocks — slow but secure. Stream Cipher: encrypts bit by bit — fast but less secure. One-Time Pad (Vernam Cipher): unbreakable when used correctly — key must be random, same length as message, used only once.
Confusion vs diffusion
Confusion: complication introduced by substitution — makes relationship between key and ciphertext complex. Diffusion: one change in plaintext changes ciphertext in multiple positions — spreading influence of a single character.
Hashing
Provides INTEGRITY (not confidentiality). One-way mathematical function. File changes → hash changes. Requirements: any input length, fixed output length, easy to compute, one-way (pre-image resistant), collision-free. MD5 = 128-bit. SHA-1 = 160-bit. HMAC = Hashing + Symmetric Key — provides partial digital signature (integrity but not non-repudiation).
Split knowledge & M of N
Split Knowledge: separation of duties applied to cryptographic keys. M of N Control: M = minimum number of people required, N = total participants. Key Escrow: secret key divided and held by trusted third parties — government can combine to reconstruct under legal authority (fair cryptosystem).
Cryptographic lifecycle
All cryptographic systems have a defined lifespan — except the One-Time Pad. Keys must be changed periodically. Keys and encrypted data should be stored on separate systems. For sensitive keys, use split knowledge. Cryptographic lifecycle = algorithm selection → key generation → distribution → storage → retirement.

PKI — Public Key Infrastructure
PKI = Symmetric + Asymmetric + Hashing + Digital Certificate. Standard: X.509. Provides P A I N for parties previously unknown to each other.
1Certificate Authority (CA) — issues and signs certificates. Verifies identities.
2Registration Authority (RA) — assists CA in identity verification. Offloads CA workload.
3Certificate — binds a public key to an identity. Signed by CA using CA's private key. Standard: X.509.
4CRL — Certificate Revocation List — list of revoked certificates. Checked before trusting a cert. Causes latency.
5OCSP — Online Certificate Status Protocol — real-time cert status query. Returns: valid / invalid / unknown. No latency vs CRL.
6Certificate lifecycle — Enrollment → Verification → Revocation. Change requires recertification.
Cryptographic attacks
Brute Force
Trying all possible keys until the correct one is found. Effectiveness depends on key length — longer keys exponentially increase effort. Work function determines feasibility.
Frequency Analysis
Exploits letter frequency in natural language. Effective against simple substitution ciphers (e.g. ROT3/Caesar cipher). Modern algorithms are designed to resist this.
Known Plaintext
Attacker has both ciphertext and corresponding plaintext. Uses the pair to deduce the key. Weaker algorithms are vulnerable.
Chosen Plaintext
Attacker can choose arbitrary plaintext and obtain the corresponding ciphertext. Allows targeted analysis of the encryption algorithm.
Meet-in-the-Middle
Attacker has known plaintext. Attacks double encryption by encrypting from one end and decrypting from the other simultaneously. Weakness of 2DES — reason 3DES uses 3 keys.
Birthday (Collision) Attack
Exploits probability that two different inputs produce the same hash value. Targets hash functions. Based on birthday paradox — collisions occur far sooner than expected. MD5 and SHA-1 vulnerable.
Replay Attack
Intercepts valid transmission and retransmits it later to gain unauthorized access. Countered by: timestamps, nonces, sequence numbers, and one-time tokens.
Man-in-the-Middle (MitM)
Attacker secretly intercepts and potentially alters communication between two parties. Countered by: mutual authentication, PKI, digital certificates, and out-of-band verification.
The three foundational access control models
Bell-LaPadula
Confidentiality
Simple Rule: No Read Up (NRU)
Star (*) Rule: No Write Down (NWD)
State Machine + Information Flow model. A subject cannot read data at a higher classification. A subject cannot write data to a lower classification. Covert channels are NOT addressed.
Biba Model
Integrity
Simple Rule: No Read Down (NRD)
Star (*) Rule: No Write Up (NWU)
Information Flow model. Inverse of Bell-LaPadula. Maintains internal and external object consistency. Covert channels are NOT addressed. Simple → Read; Star → Write.
Clark-Wilson
Integrity
CDI — Constrained Data Item (protected)
UDI — Unconstrained Data Item
IVP — Integrity Verification Procedure
TP — Transformation Procedure
Enforces Segregation of Duties. Uses a constrained interface. TP is the only procedure allowed to modify CDI. Enforces well-formed transactions.
Other security models
Brewer-Nash (Chinese Wall)
Protects against conflicts of interest. A subject who accesses one object cannot access objects in conflict with it. Used in financial and legal industries to prevent insider trading.
State Machine Model
System is always in a secure state regardless of its current state. Every possible state transition must preserve security. All inputs must be evaluated against security policy before execution.
Information Flow Model
Prevents unauthorised flow of information between different security levels. Both Bell-LaPadula and Biba are based on this model. Controls direction of data movement between classification levels.
Non-Interference Model
Actions taken by subject A must not affect or be noticed by subject B. Goguen-Meseguer Model is a non-interference model. Sutherland Model extends this to prevent covert channels.
Take-Grant Model
Dictates how rights can be passed between subjects and objects. Four rules: Take (take rights over an object), Grant (grant rights to an object), Create (create new rights), Remove (remove rights). Access Control Matrix shows subject-object permissions.
Graham-Denning Model
Focuses on secure creation and deletion of both objects and subjects. Defines eight protection rules for managing access rights during creation/deletion lifecycle.
TCB — Trusted Computing Base
TCB = Hardware + Software + Firmware. All protection mechanisms that work together to process sensitive data. It defines the total combination of protection mechanisms within a computer system.
Security Perimeter
Imaginary boundary separating the TCB from the rest of the system. Any communication crossing the perimeter must be mediated by the Reference Monitor.
Reference Monitor
Mediates access between all subjects and objects. Enforces access control policy. Must be: always invoked, tamper-proof, and small enough to be verified. The Security Kernel implements the Reference Monitor concept.
Confinement, Bounds & Isolation
Confinement: process can only read/write from a certain memory area (e.g. sandboxing). Bounds: the memory limits a process cannot exceed. Isolation: when a process is confined through bounds, it runs in isolation from other processes.
Security modes (S.C.A.N.)
Four system modes by clearance level: Dedicated (all users have clearance/approval/need-to-know for all data), System High (all users cleared for highest level but need-to-know varies), Compartmentalized (clearance for highest but formal approval varies), Multilevel (users may differ in clearance, approval and need-to-know).

TCSEC — Trusted Computer System Evaluation Criteria (Orange Book)
Created by DoD (Department of Defence). Part of the Rainbow Series. Protects Confidentiality only. Orange Book = standalone systems. Red Book = network security. Green Book = password management.

Globally accepted evaluation criteria. Tests a Target of Evaluation (TOE) against a Protection Profile (customer needs) and Security Target (vendor's security claims). Certification = internal technical evaluation. Accreditation = formal management acceptance by a third party.

ITSEC — IT Security Evaluation Criteria (Europe)
What is ITSEC?
European alternative to TCSEC. Developed as a joint standard by France, Germany, Netherlands, and UK. Unlike TCSEC, it evaluates CIA (Confidentiality, Integrity, Availability) — not just confidentiality. Uses a separate functionality class (C1-A equivalent) plus assurance level (E0-E6).
TPM & HSM
TPM (Trusted Platform Module): crypto processor chip embedded in hardware — stores and processes cryptographic keys for hardware-supported hard drive encryption. HSM (Hardware Security Module): dedicated crypto processor used to manage/store digital encryption keys, accelerate digital signatures, and improve authentication. More powerful than TPM.
Secure design principles
Security should be "baked in" rather than "bolted on." Every design decision must consider security from the outset — not retrofitted after deployment.
Defence in depth
Layered security controls — if one fails, others remain. Applied in series (sequential) and parallel (redundant). No single point of failure for security. Multiple overlapping controls are required for robust protection.
Least privilege
Every subject (user/process) is granted only the minimum access rights required to perform its function. Reduces the attack surface significantly. Applies to users, processes, services, and applications.
Separation of privilege
Requires multiple conditions or approvals to grant access. No single individual or process should have unchecked authority. Enforced through multi-person integrity rules (M of N control).
Abstraction
Hides implementation details — users interact with a simplified interface. Used for classifying data and assigning roles. Prevents direct manipulation of underlying data structures. Enables security without exposing internals.
Data hiding
Restricts access to data structures — only specific processes/objects can access certain data. Cell suppression is a data hiding technique. Prevents inference attacks on databases.
Layering
Implementation of multiple rings of protection (Ring Model: Ring 0 = kernel/most privileged, Ring 3 = user/least privileged). Each layer provides security independently. Applications must use system calls to access lower privilege layers.
Open design
Security should not depend on the secrecy of the design — only on the secrecy of the key (Kerckhoff's Principle). Open systems allow independent verification. Security through obscurity alone is not sufficient.
Trusted recovery
If a system fails, it must recover to a secure state where all security controls remain intact. System should not expose vulnerabilities during or after a crash. Recovery procedures must be planned and tested.
Cloud computing & virtualisation
SaaS
Software as a Service — fully functional applications accessed via browser (Gmail, Office 365). Maximum responsibility with Cloud Service Provider (CSP). Least control for the customer.
PaaS
Platform as a Service — CSP provides OS and hardware platform. Customer builds and deploys applications. CSP responsible for underlying infrastructure maintenance.
IaaS
Infrastructure as a Service — provides basic virtualised computing resources. All maintenance performed by the consumer. Full control over virtualised hardware, memory and storage.
Virtualisation
Guest OS instances running on a single physical host via a Hypervisor. Advantages: scalability, quick recovery, efficient resource use. Threats: malicious code compromising the hypervisor or guest OS. Virtual machine escape is a key concern.
TPM vs HSM
TPM: embedded chip providing hardware-based cryptographic functions for a single device. HSM: dedicated external device managing keys for enterprise environments — supports faster signing and bulk operations. Both provide tamper-evident key storage.
IoT / Embedded security
Methods: network segmentation, logical and physical isolation, application firewalls, manual firmware updates, firmware version control, wrappers (encapsulation), redundancy and diversity. SCADA/ICS systems (DCS, PLC) require special security attention. Stuxnet targeted SCADA/PLC systems.

Common architecture flaws & vulnerabilities
No software should be trusted by default. The primary focus of an OS is to keep the computing environment stable and keep processes isolated from each other.
Covert Channels
Communication over an unauthorised channel not designed for communication. Opposite = Overt Channel (authorised). Two types: Covert Timing Channel (modifying resource timing — difficult to detect) and Covert Storage Channel (writing data to shared storage for another process to read). Defence: code review and auditing.
Backdoors & Trapdoors
Backdoor: deliberate entry point bypassing normal authentication. Maintenance Hook (Trapdoor): backdoor left by developers to fix production issues — must be removed before release. Both represent serious vulnerabilities if left in production code.
Buffer Overflow
Writing more data to a buffer than it can hold — overwrites adjacent memory. Can allow arbitrary code execution. Defence: input validation, bounds checking, stack canaries, ASLR (Address Space Layout Randomisation), DEP (Data Execution Prevention).
TOC-TOU (Race Condition)
Time of Check – Time of Use. A subject checks an object (TOC), decides to use it, but between TOC and TOU the object changes. The attacker exploits this time window. Affects file permissions, database transactions, and authentication checks.
Salami Attack
Small amounts are stolen repeatedly on the assumption they will go unnoticed. Common in financial systems — rounding fractional cents to attacker's account. Accumulates into significant theft over time.
Data Diddling
Small changes made to data during input/processing/storage or output transactions. Modifications are subtle enough to go unnoticed. Difficult to detect without comprehensive audit trails and input/output validation.
Database: Aggregation
Combining multiple pieces of non-sensitive information to create sensitive information. Example: individual salary ranges + job titles + department headcount = specific salary inference. Defence: data classification and access controls on combined queries.
Database: Inference
Deducing sensitive information from non-sensitive responses. Attacker gains access to higher classification data through logical deduction. Countermeasure: polyinstantiation — providing different data to users of different clearance levels.
Transitive Trust
If A trusts B, and B trusts C, then A transitively trusts C. Risk: trust propagates through chains — a compromise anywhere in the chain affects all parties. Proxy systems are based on transitive trust. Defence: explicit trust policies and zero-trust architecture.
TEMPEST / Emanation
Electronic devices emit electromagnetic radiation that can be intercepted to reconstruct data. Countermeasures: Faraday Cage (special enclosure that blocks electromagnetic emissions), White Noise (random signals cause interference), Control Zone (Faraday Cage + White Noise combined). Used in sensitive government/military environments.
Database security concepts
Data Warehousing
Collection of data consolidated from multiple source databases for the purpose of analysis and reporting. Centralised repository of historical data. Security concern: aggregated data may reveal sensitive patterns not visible in individual databases.
Data Mining
Analysis performed on data obtained from data warehousing. Discovers patterns, correlations, and anomalies. Activity of data mining produces metadata. Metadata is stored in a more secure container called a Data Mart.
BYOD concerns
Key issues: data ownership and isolation, patch management, antivirus management, forensics, privacy, on/off-boarding process, adherence to corporate policy, legal concerns. BYOD policy must be signed before device use. Data isolation is critical — device owner should maintain separate personal/corporate data.
Physical security — layered defence
Physical security is the FIRST line of defence. People are the LAST. Human life is always the #1 priority — all physical security decisions must account for safe egress. Single entrance = better security. Multiple entrances = better evacuation.

Fire suppression
Remember C L E M for fire extinguisher classes. Four stages of fire: 1. Incipient (air ionisation, no smoke), 2. Smoke, 3. Flame, 4. Heat. Preaction water system = most suitable for computer rooms with humans present.
ClassFire typeSuppression material
Class ACommon combustibles (wood, paper)Water, soda acid
Class BLiquid fires (fuel, oil)CO₂, Halon, soda acid
Class CElectrical firesCO₂, Halon (FM-200) — never water
Class DMetal firesDry powder
Water suppression systems
Wet Pipe: always filled with water. Dry Pipe: contains compressed air — water flows only when activated. Deluge: large pipes delivering huge water volume — NOT suitable for computer rooms. Preaction: combination of dry and wet pipe — most suitable for computer rooms with occupants.
Halon & FM-200
Halon suppresses fire by interrupting the chemical chain reaction. Banned by Montreal Protocol — depletes the ozone layer. FM-200 (HFC-227ea) is the modern replacement — safe for humans and electronics. CO₂ suppresses by removing oxygen — dangerous for occupied spaces.
Temperature & fire damage
100°F / 38°C: magnetic storage tapes damaged. 175°F / 79°C: hardware (RAM, CPU) damaged. 350°F / 177°C: paper products ignite. Computer room target: 15°C–23°C temperature, 40–60% humidity. Static voltage: 40V destroys circuits, 17,000V permanent circuit damage.
